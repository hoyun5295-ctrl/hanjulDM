## §0 불변 원칙 (어길 수 없는 것)

1. **편집기를 만들지 않는다.** 사장님 손질은 4종뿐 — 가격(키패드)·상품 빼기·상품명 1줄·「다른 느낌」. 그 외 입력 UI 신설 금지.
2. **자동 채움은 자사 소유물만 확정한다.** 카탈로그 → POS 보유 이미지 2단까지. 네이버는 어떤 경로로도 자동 확정 금지(후보 제시 전용).
3. **인쇄물에는 로컬 파일 이미지만 들어간다.** 외부 URL 렌더 주입 금지(핫링크 차단). 네이버 유래 이미지는 인쇄·POP 매체 진입 금지.
4. **발행 시점에 디자인이 굳는다.** variant·엔진·스키마 버전을 행에 스냅샷 — 재열람은 언제나 같은 모습.
5. **소비처 0인 모듈은 완료가 아니다.** tsc 통과는 완료 근거가 아니다 — 소비처 검증 테스트가 판정한다(§8).
6. **노출 조합은 실렌더로 확인된 것만.** 검수 안 된 엔진×시즌 조합을 사장님에게 열지 않는다.

## §1 화면 설계 — 화면 1개 · 1상태머신

### 1-1. 홈 3카드 = 초기 상태 프리셋 (화면 분기 아님)

| 카드 | 초기 상태 | 산출 매체 |
|---|---|---|
| 이번 주 행사 | **지난 전단 복제**로 열림(기간만 이번 주로 이동). 1주차(복제 대상 없음)는 소스 칩 유도 | URL + POP (+인쇄 뽑기) |
| 오늘 급처분 | 1품목 슬롯만 열림 — 상품 1 + 가격 1 = 5초 산출 | POP + URL. ⚠ 카드 문구는 "산출"로 — "고객에게 보낸다"로 읽히면 안 됨(발송은 별도 행위) |
| 명절·시즌 | 시즌 프리셋 강제 + 인쇄 동반 흐름 | URL + POP + 인쇄 |

카드는 `FlyerComposer` 한 컴포넌트의 초기 파라미터다. 카드마다 흐름이 갈리면 목록/폼 2모드 표류 사고(죽은 미러 280줄)를 3배로 반복한다 — **1화면 1상태머신, 카드는 파라미터.**

### 1-2. 소스 4칩 (상단 1열 고정)

POS 인기 / 지난 전단 / 카탈로그 / 엑셀AI. 칩 탭 → 바텀시트에서 **체크만**(입력칸 0) → 담는 즉시 미리보기 갱신. 현행처럼 카테고리 탭 안 하단 버튼에 묻지 않는다(현 FlyerPage.tsx:816~830).

### 1-3. 미리보기 = 발행 (SSOT)

- 미리보기 원천은 `preview-html`(short-urls.ts) 하나. 프론트 미러 렌더러(`FlyerPreviewRenderer` :1028~1306 약 280줄 + `ENGINE_MAP` :984)는 **삭제**하고 "미리보기 HTML = 발행 HTML" 계약 테스트 1본으로 잠근다.
- 낙관 패치는 가격·상품 빼기 2종만, 그것도 **자릿수 계급·수량 밴드가 불변일 때만**. 경계를 넘으면 350ms 디바운스 서버 재렌더(deps 해시에 밴드·자릿수 키 포함 — FlyerPreview.tsx:126 정비).
- iframe은 축소 렌더(scale=w/393)이므로 편집 히트영역은 iframe 밖 오버레이 레이어로 분리.

### 1-4. 손질 4종 (전부 미리보기 위에서)

①가격 탭 → 숫자 키패드 팝오버 ②상품 X ③상품명 1줄 수정(POS 축약어 "삼겹100g" 정정 통로 — 회의론자 수용분) ④「다른 느낌」 1버튼 = 엔진·변형 재추첨. 단 **선택된 매체 등급 안에서만 순환**(급처분 POP 흐름에 STORY 엔진이 나오면 안 된다 — 매체 적합도 표는 template-recommender가 소유).

### 1-5. 발행과 인쇄 관문

- 발행 = 하단 고정 바 1버튼(URL 발행 + POP 뽑기 진입). 저장→목록→발행으로 끊지 않는다.
- **인쇄만 분리 관문**: [인쇄 뽑기] → 확인 시트 = 상품명·가격·**이미지 출처** 3열 리스트(POS·카탈로그 원본과 다른 값만 상단 diff 하이라이트) + 자동 매칭 이미지 포함 시 명시 동의 체크 → PDF. 편집 화면이 아니라 발주 확인이다. 이미지 출처가 실제 3열에 표시되어야 성립(동의 체크만 있으면 책임 전가 장치일 뿐).
- POP은 별도 페이지가 아니라 같은 완성본의 [POP 뽑기] — 상품 승계, 프리셋 3개(A4 1장/분할/프라이스카드). `pop-preview-html` 신설(현행 PopPage는 미리보기 0, PDF로만 확인 + native prompt 3회 — 폐기).

### 1-6. 즉시 제거 잔재

- `handleSave`의 "AI 상품 이미지 생성" 안내 + `/generate-images`(DALL-E) 호출(FlyerPage.tsx:97~102, flyers.ts:471~) — 방침 정면 충돌.
- `PopPage.tsx` native `prompt` 3회(:463~479) — 커스텀 모달 규율 위반.

```
[소스 4] ─ normalizeProductInput() ─→ FlyerRenderItem[]
              (POS flyer_pos_promotions · 엑셀 MappedProduct · flyer_catalog · 복제 categories)
   → fillImages()          자사 2단: 카탈로그 → POS 보유 (네이버는 여기 없음 — §3)

   → recommendTemplateAndSeason()  template-recommender.ts:302 — 매체 등급 필터 추가
   → recommendDesign()     claude-design-renderer.ts:191 (fixedTemplateCode 결합)
   → renderTemplate(code, data, { variant })   ★ 시그니처 확장 — variantToStyleBlock을 엔진 <style> 뒤에 주입
```

- 배선 지점 = 신규 `POST /flyers/auto-build` 1곳 + flyers.ts:366 INSERT 폴백(template 미지정 시). 죽어 있던 recommendDesign·recommendTemplate·(§5) media-images가 여기서 산다.

- 복제 = `POST /:id/copy` 확장(기간 갱신 + 가격 시트 진입). POS 최신가 자동 재조회(/reissue)는 2차.
- **선행 실측(구현 착수 전):** ①pos-auto INSERT 컬럼 불일치 의심 — flyer-pos-auto.ts:159 `created_by` vs 전 경로 `user_id`, try/catch가 삼키는 중(무성 실패 가능) ②POS 이미지 보유율(회의론자 조건 a — 보유율이 낮으면 슬랩이 기본 화면이 되므로 §4 순서가 바뀐다). 실측 SQL은 구현 세션에서 하나씩 제공.

### 2-1. 스냅샷 DDL (신규 테이블 0 · flyers ALTER 4컬럼)

## §3 이미지 정책 — 네이버 강등

검수 확정 사실: 현행은 첫 결과 무검증 채택(flyer-naver-search.ts:216~223), 이미지 검색 API 상시 선호출(제3자 저작물이 서버 복제 후 인쇄 배포되는 구조), 429/401을 빈 결과로 삼킴, 전 검색에 `' 식품'` 강제 접미(:117), 저장 경로 `process.cwd()`(:21 — 이중 경로 404 사고 계열).

1. **자동 확정 = 자사 소유물 2단만** (카탈로그 → POS).
2. **네이버 = 후보 제시 전용.** 자동 경로는 쇼핑 API만 호출. 이미지 검색 API는 사장님 수동 선택 UI에서만. 확정은 항상 사람 탭 1회.
3. **신뢰도 게이트 전에 쿼리 정규화부터**(회의론자 파열점 2): POS 축약어 정제("삼겹100g"·"홈런볼*2") + `' 식품'` 접미 제거 → 그 위에 상품명 토큰 교집합 게이트. 미달 = `imageUrl=null` → §4 슬랩 폴백.
4. **PB·신선식품·주류 = 자동 매칭 대상 제외** (PB는 경쟁사 사진이 붙고, 신선은 정답 개체가 없고, 주류는 쇼핑 API 미노출).
5. **인쇄 경로 로컬 파일만**(회의론자 조건 b): image-pipeline.ts:92~94의 외부 CDN URL 직주입을 차단 — 다운로드 성공분만, 실패 시 무이미지 폴백(빈칸·깨진 아이콘 금지). 단일 POP에 `onerror` 부재도 함께 정리.
6. 429/401 상태코드 표면화 + 일일 쿼터 카운터(키 전 매장 공유 — 소진 시 "이미지 후보 일시 중단" 정직 표기). 저장 경로 env 기준 통일.

## §4 렌더 품질 — "어떤 입력이 와도 완성"

**1차 필수**
1. **무이미지 = 1급 비주얼 승격 3단**: ①스펙 조판 슬랩(산지·등급·중량·당일입고 활자 — POSTER footrow 셀 :2536~2541 원형 확장) ②카테고리 연출 배경(GRID HERO radial+grain :1795~1796을 categoryBg 15키와 결합) ③단색 SVG 픽토그램 15종 자체 제작(이모지 폴백 폐기 — OS별 모양 상이). 이미지 유/무 상품은 섞지 않고 그룹핑해 섹션 분리.
2. **상품 수 밴드 3단 분기: ≤6 / 7~20 / 21+** (회의론자 조건 d — 자동 결정의 선행 조건. 밴드 없이 자동만 켜면 25품목이 3품목 레이아웃에 얹혀 "자동=망가짐" 1회 학습으로 신뢰 붕괴). 밴드별 컬럼 수·hero 개수·섹션 삽입 주기.
3. **상품명 길이 계급화**(≤8 / ≤16 / 초과 → font-size 클래스 서버 부여) + 프로모 토큰(1+1·2+1) badge 자동 분리 추출.
4. **가격 자릿수 스케일** 토큰화(1,290원과 129,000원이 같은 폭인 현행 고정 pt 폐기).
5. **POP 시즌 토큰 실배선** — 본문 하드코딩 색(#dc2626 등)을 var(--color-*)로(현재 참조 0건). POP 신규는 **매대 띠지 1종만**.

**2차 이연**: pickHero SSOT(카톡 og와 본문 주인공 통일 — 현재 불일치), 시즌 8→12(가정의달·복날김장·B급 떨이·프리미엄 명절), POP 용도 7종 확장, 혼합 종횡비 정리.

## §5 6매체 토큰 정합

- URL: `generateMediaCssBlock('url', token)`을 renderTemplate에서 prepend(현재 미경유). 엔진 `:root`가 media 블록을 덮지 않게 주입 순서 검증.
- POP: `'default'` 하드코딩(flyer-pop-templates.ts:94) → 실토큰.
- 인쇄: paged-pdf.ts:75가 항상 'default' — 호출 라우트에서 `resolveSeasonToken` 결과 전달.
- **인쇄 제2 SSOT(print/design-tokens.json) 병합**: 컬러는 season-tokens로 단일화(현재 인쇄만 브랜드 인디고 — 6매체 중 인쇄만 색이 다르다), typography 6역할·PAPER-SIZES는 print 쪽 유지. ⚠ 병합 후 **인쇄 9종(5종 양면 포함) 실렌더 재검 의무** — 백지 사고 재발 반경(회의론자 파열점 6).
- MMS·알림톡 PNG(media-images 배선 + og-image puppeteer PNG화)는 **2차** — W4 결과 폐회로(11번 문서 A) 완성 전에는 발송 매체를 켜지 않는다.
